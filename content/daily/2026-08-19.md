### 2.2 预处理与预测/评价总体

- 特征按**同一交易日横截面**做 robust z-score：优先 MAD，退化时依次使用 IQR、标准差，并 clip 到 `[-10, 10]`。任何日期若出现不满足合同的关键异常，按 fail-closed 处理。
- 拟合目标也按日做 `MAD → IQR → std → clip10` 的稳健变换；模型训练优化的是 transformed target。
- Final RankIC 和组合收益使用原始 `raw_return`，不是 transformed target。
- 预测总体是“当日特征 key 唯一、至少一个原始特征有限”的股票；评价还要求 prediction、score、raw return 均有效。

### 2.4 时间权重、seed 与选择规则

- 所有 family 都试了半衰期 `H ∈ {120, 60, 40, 20}`。
- 日期年龄权重为 `2^(-age/H)`；再除以当日有效股票数做 date balance，最后在该次 fit 的全部行上归一化到均值 1。
- broad seed 为 `20260804`；随机 family 的完整 seed 集为 `{20260804, 20260817, 20260831}`。
- primary selection metric 是 outer OOF 的 `mean_daily_rankic`，日内并列 rank 使用 average rank。
- inner/cross-family 选择使用 moving-block bootstrap，block length 5、2,000 次；先取表现最优，再使用 paired SE 与 parsimony 规则选择统计上不可区分但更简单的配置。故“最终选择配置”不一定等于未经收缩的 raw observed maximum。
- 随机 family 先用 broad seed 全搜，再对前 5 个候选扩展至三个 seed；promotion 的 paired-SE multiplier 为 2.0。
- Development 报告置信区间使用 MBB 5,000 次；正式 Final primary test 使用 MBB 10,000 次。

### 2.5 计算后端

- 线性、PCR/PLS、树、GAM、HistGBRT 在 CPU 路径；单模型库线程通常固定为 1，以避免候选间隐式线程差异。
- AE 两个 family 使用 `cuda:0`、float32 encoder；ridge head 使用 GPU float64 sufficient statistics，并对 CPU reference 做等价门。
- 正式 LightGBM 使用 CUDA quantized histogram：`use_quantized_grad=true`、256 grad bins、全 834,669 fit rows 建 bin、3 seed ensemble。
- XGBoost Development 被登记为 GPU allowed family；但后续 all-14 Final 补充结果实际是 CPU `hist` 实现，不能称为冻结的 CUDA Final。
- HistGBRT 训练线程为 1。Attribution 的实际 inference 为 8 线程；旧 numerical/stage 文本中的 14 只是未生效陈旧声明。审计 sidecar 已确认 6 个 outer attribution unit 全部记录 8 线程，且不改变候选、OOF、champion 或 Freeze。

## 5. Final：14 模型放在同一张表

### 5.1 计算口径

- `RankIC`：每天对 continuous score 与 raw return 计算 Spearman correlation，再对 55 天等权平均。
- `纯多 Top20%`：每天买入预测分数最高 20% 的股票，等权毛收益。
- `纯空 Bottom20%`：每天卖空分数最低 20% 的股票，收益记为负的底部组合原始收益。
- `多空 Top10%-Bottom10%`：每天买入最高 10%、卖空最低 10%；一份多头加一份空头，gross exposure=2。
- 三种组合都报告 `年化均值 / 年化波动 / Sharpe`。年化均值=`daily mean×252`；年化波动=`daily sample std×sqrt(252)`；Sharpe=`daily mean/daily sample std×sqrt(252)`。
- 主表采用 **fractional tie-preserving** 分位权重：若大量同分股票跨越分位边界，整个同分块按相同比例分配，从而保持精确 20%/10% 质量且不依赖股票代码顺序。
- 全部是 gross return：没有手续费、滑点、冲击成本、容量、停牌/涨跌停成交约束，也没有无风险利率扣减。

### 5.2 表格怎么读

1. **先看证据层**。只有冻结的 regression tree、raw ridge、raw elastic-net、正式 CUDA LightGBM 是确认性 Final；其余 10 个 family 的 Final 数字是看过标签后的补充描述。
2. **RankIC 和 Sharpe 回答不同问题**。RankIC 衡量整个横截面的单调排序；Top/Bottom Sharpe 只看尾部分组。PLS 的 Final RankIC 和多空 Sharpe 都高，但这只有 55 天且是 post-hoc，不能据此推翻 Freeze。
3. **纯多为负而纯空为正很普遍**。这说明该区间总体多头底盘偏弱、信号的空头侧更有贡献。多空组合可因共同行情暴露抵消而显著降低波动。
4. **55 天年化很不稳定**。例如 PLS 多空 Sharpe 10.176 和 AE 7.381 都来自很短样本、无成本毛收益，不能直接当作可实现的长期 Sharpe。
5. **不要把 Development ICIR 当 Sharpe**。ICIR 的分子/分母是 daily RankIC；本表 Sharpe 的分子/分母是每日组合真实收益。

### 5.3 LightGBM 为什么前后不同

这不是指标函数随机算错，而是同一 family、同一 L02 参数和同一 seed 集用了不同训练实现：

- 正式生命周期 business revision 是 `9145ecaef84290bb1af4b4c3aaa7992daaf72d28`；成功的 all-14 post-hoc operational revision 是 `c7358ee8900a2e231929ad7ab1813cb21efaf091`。后者绑定前者的精确 Development selection，但不是同一数值实现身份。
- 正式模型对象：`device_type=cuda`，`use_quantized_grad=true`，256 grad bins，`force_row_wise=true`，全 834,669 行建 bin。
- all-14 post-hoc 模型对象：`device_type=cpu`，`use_quantized_grad=false`，`force_col_wise=true`。
- 两个 prediction key 完全相同，但 `scores_bitwise_equal=false`，最大绝对 score 差为 **1.3908131887**。
- 因而正式 CUDA RankIC=0.006065、LS Sharpe=0.226；post-hoc CPU RankIC=0.012216、LS Sharpe=4.944。权威冻结结果必须使用 CUDA 行，CPU 行只说明“另一实现会得到什么”。
- raw ridge、raw elastic-net、regression tree 在正式与 post-hoc 之间 score 逐位一致，说明共同的评价代码没有制造差异。

XGBoost 只有 post-hoc CPU Final；没有满足冻结 CUDA identity 的 XGBoost Final，因此不能把 CPU 行伪装成正式 XGBoost Final。

### 5.4 并列分数（ties）敏感性

fractional tie-preserving 是主口径。若强行按股票代码稳定排序后用整数 floor 截断，同分股票会被代码顺序任意拆开：

- regression tree 每日分位边界都穿过大同分块，最大同分块 1,669 只股票。exact-code-order 的 long/short/LS Sharpe 为 `-0.571 / 5.002 / 5.637`，主口径为 `-1.924 / 3.851 / 5.805`。
- 正式 CUDA LightGBM 最大同分块 2,806，只因量化 score 产生。exact-code-order 的 long/short/LS Sharpe 为 `-2.063 / 4.992 / 4.947`，主口径为 `-3.118 / 3.139 / 0.226`。
- 其他 post-hoc family 没有跨越分位边界的大同分块。

因此，tree/quantized-LightGBM 的尾部组合对 tie convention 敏感；fractional 结果更中性，因为它不让股票代码成为隐含 alpha。

- 与 all-14 JSON 的三类 Sharpe 最大绝对差约 `1.07e-14`。

## 6. 为什么其余 10 个模型没有进入 Freeze

Freeze 不等于“只训练了 4 个模型”。14 个 family 都完成了候选搜索、outer OOF、attribution 和 Development validation。4 条 Freeze pipeline 的角色是：

| 角色 | Pipeline |
|---|---|
| confirmatory primary | regression_tree T02 / H=120 |
| raw linear baseline | raw_ridge R06 / H=40 |
| sparse linear baseline | raw_elastic_net EN15 / H=40 |

### 7.2 相关簇

按 Development fold 内加权相关构造距离 `1-|corr|`，average linkage，cutoff=0.3（约等于 `|corr|≥0.7`）：

- 每折有 13–14 个多特征簇，覆盖 107–109 / 127 个特征；18–20 个 singleton。
- 最大稳定簇约 35 个特征，聚合 cancel/cfrac、algo breadth、spread thin、OFI、trade-flow 等共同强度。
- 第二大簇约 23–25 个，主要是 repost、residual、queue、split/merge、liquidity-switch。
- 另有约 13 个特征组成 price-save、aggressive repost、reprice、adaptive/reactive、book queue/deplete/spread 相关簇。

这说明许多“不同名字”的微观结构因子事实上共享很强的横截面状态；归因应优先看簇/层级，而不是只看单列排名。

### 7.3 ICA / IPCA / conditional AE

- ICA 诊断维度为 `{5,10,20,40}`，每个维度 3 seed；40 维最难收敛，约 128–370 次迭代。它只用于非高斯独立方向诊断，不生成可选预测。
- IPCA 维度为 `{1,2,3,5,8,10}`，最终 objective 约 `4.28e-05–4.44e-05`；用于历史结构重构，不是 Final pipeline。
- conditional autoencoder 维度 `{1,2,3,5,8,10}`、每维 3 seed、CUDA，通常 42–60 epochs；`prediction_eligible=false`，只回答“低维条件表示能否重构历史结构”。
- 三类 structural diagnosis 都没有访问 restricted labels，也没有输出可参与 Freeze 的 prediction artifact。

## 12. 应如何评价当前模型

- **正式最可信结论**：regression tree 的 55 日 Final RankIC 为正，MBB 单侧检验通过；但样本仍短，且尾部组合受大同分块影响。
- **线性模型**：Development RankIC 多为负；Final 的空头侧普遍为正，raw ridge 多空表现较好，但 raw elastic/lasso 的 Final 排序为负。
- **非线性 boosting**：Development OOF 组合收益突出，但 RankIC 优势小；LightGBM 对 CPU/CUDA 数值实现高度敏感，任何汇报必须带 backend identity。
- **低维表示**：PCA 明确显示强低维结构，但“存在低维结构”不等于“PCR/PLS 能稳定预测”。representation gates 均未通过。
- **AE/PLS 的高 Final 数字**：值得作为下一轮预注册研究假设，但由于它们是 labels-open 后 post-hoc 结果，不能当成已确认 alpha。
- **实盘可实现性**：当前没有费用、冲击、借券、容量、成交和换手约束；任何 Sharpe 都只是研究诊断，不能直接用于资金配置。

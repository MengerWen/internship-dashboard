# 10.14｜沪市委托 v2 全流程提速与代码优化

本次优化覆盖沪深各十一日的原始委托 v2 研究。约 **1.82 亿笔投影订单**保持原规则、已拟合参数和固定种子，每笔仍保留 **20 组抽样**。完成 25 组估计、三个留出日的重叠比较与前向核对、十三日官方十档快照及最终输出合同验收。

日期为 **10.14**，分类为 **提速**。主要效果是：完整留出日的评分流程 **295.76 → 74.62 秒，快 3.96 倍**；对应 guard 峰值 **17.45 → 1.65 GiB，减少 90.6%**。前向核对的真实接续撮合阶段平均使用 **15.89 和 15.95 核**，接近用满账户的 16 核预算。

这些是计算效率改进，不代表还原精度提高。三个深市留出日的 v2 限价点估计未优于 v1；隐藏撤余概率仍有校准偏差。v1 默认入口、沪深参数隔离、未知状态和两套沪市尾部方案均保留。

## 一、减少概率估计中的重复计算

**1. 共用批次概率状态。** `TickHazard.prepare` 和 `PreparedHazard` 先计算同批协变量的线性项、累计危险率与条件归一项。条件分位数、众数、区间概率和二十次抽样复用这份状态，减少相同矩阵运算、指数计算和条件分布重建。`TailReference.prepare` 沿用同一方式处理尾部拼接，沪深模型参数各自保留。

**2. 似然按有界批次并行归约。** `likelihood_gradient` 和 `fit_tick_hazard` 复用原数学公式，在 16 核总预算内调度独立批次，按固定顺序归约似然与梯度。这里验收的是内核能力；已完成的两个模型直接复用，没有为了测速重新拟合整个模型。

**3. 批量查找隐藏撤余分组。** `HiddenRemainder.probability`、`excess_quantile` 复用特征和分组条件，批量定位订单、查找稀有深度密度与经验分布，减少逐行组键生成、反复宽表复制和重复 CDF 查找。卖方或缺少识别变异的分组继续保留未知，不能用端点填补。

**4. 类型集合向量化。** 用整数位掩码批量处理可行类型、识别状态和类型评分，减少逐行 Python 集合与循环；供应商合并类型仍按合法类型集合评价，不增加任意类型先验。

**5. 抽样保持列式表示。** `OriginalV2.estimate` 按有界批次执行，二十组抽样使用 Arrow 的 int64 list 列保存，通过 `write_order_page` 写入通用 Parquet 列表。进程间不再先把全部抽样逐行变成 Python 对象；大整数身份、空列表和未知值保持精确。

**6. 随机数绑定订单身份。** 继续复用 `keyed_uniform`，随机数绑定稳定订单身份和种子 `20261013`。线程数、批次宽度、领取任务顺序和完成顺序改变时，抽样离散值仍一致；限价和撤余沿用各自的独立随机流。

## 二、逐页评分、异步发布与断点复用

**7. 从整日宽表改为逐页精确评分。** `EstimateScorecard` 和 `EstimateScoreAccumulator` 每次只读取评分需要的数值及分层列，再调用原 `score_estimates`。整数分母、误差直方图和校准计数用 `Counter` 归约；全局 AUC 保留必要的概率和真值数组，最后使用原精确秩算法计算，不能平均各页 AUC。

**8. 数量假设只保留参与检验的行。** 先筛出实际用于隐藏数量分布检验的少量订单，再复用原检验函数，避免为少量真值展开整日抽样宽表。完整日的分组、均值、中位数和 KS 结果与参考一致。

**9. 重叠区比较复用概率状态。** `overlap_comparison` 对同一数值批次共用概率状态和归一项；比较仍使用相同沪市协变量、原网格和求和语义，程序不选择尾部方案。

**10. 本地输入优先，来源哈希验收。** `source_order_page`、`estimate_page_path` 和既有 Parquet 股票条件读取入口优先使用哈希一致的本地页，缺页才回退持久存储，减少重复 S3 读取。相关读取方式做了双顺序配对测量；个别分组没有提速，因此没有承诺所有输入都更快。

**11. 发布与下一页计算重叠。** 单发布线程负责压缩、注册、S3 保存与回读；主流程准备下一页。上一页发布异常向主流程传播，末尾等待全部发布结束。推理与发布的同时核需求计入统一预算，生产估计最多给推理 15 线程、为发布预留 1 核。

**12. 完整日期和关闭页可安全接续。** 页先写临时文件、完成输入与模型收据，再原子改名并登记。复用前核对版本、规则、模型、种子、订单键和文件 SHA；关闭但尚未注册的本地页也能凭完整收据恢复。已经完成的八个日期、模型和订单页保持不变，性能接续新增 SQL 为 0。

**13. 规则等价与科学身份独立核对。** 公共绝对申报价公式提取后，核对展开表达式的完整 AST 等价，允许有明确证明的旧模型复用。前向身份还绑定事件规范化、基础盘口、沪市盘口和类型解码依赖；跨 Python 版本使用规范 AST，避免仅因空的可选语法字段改变而误判科学身份。

## 三、让前向核对持续使用可用 CPU

**14. 共用只读 Arrow 股票行段。** `prepare_inputs`、`stock_row_runs`、`mapped_table` 和 `stock_frame` 每个输入页只解码、索引一次。工作进程通过内存映射读取本股行段；IPC 传路径和行段描述符，避免传整份 pandas 表及逐行抽样对象。同股多段按来源顺序合并。

**15. 持续调度替代整批等待。** `run_stocks` 用 `FIRST_COMPLETED` 回收已完成任务并继续派发，避免每批 32 股都要等待最慢股票。按预计字节数优先启动大股票，计算队列按字节准入，总预留上限 16 GiB；股票内消息因果顺序保持原样。

**16. 读取准备和撮合分开配置。** 准备阶段最多 8 个进程，撮合阶段按账户余量准入到 16 个进程，进程内数值线程为 1。全部线程、队列和祖先 cgroup 内存余量一起考虑；外层 guard 为 100G、16 核，交易窗口仍由既有冻结机制处理。进程数不是核利用率，验收使用实际 CPU 秒除有效墙钟。

**17. 为重复撮合建立精确盘口索引。** `PreparedMatchingDepth` 对同一进场前盘口只验证一次，建立价格优先序和数量前缀和，再用价格二分和数量二分定位成交范围，减少每个抽样重新扫描、复制所有档位。数量累计使用 Python 整数；七类订单、五档边界、保护限价、空盘及超过 int64 的累计量均做差分核对。

**18. 相同抽样共用结果，按重复次数计权。** `forward_scenarios` 缓存相同数量、限价和类型集合的情景；同订单的两套尾部方案字段完全相同时共享一次撮合。实际可见统计只生成一次，重复结果按二十组抽样中的出现次数加权；每套方案的分母独立保存，不少算抽样。

**19. 已完成股票在读入前跳过。** 先核对逐股收据和兼容身份，再准备剩余股票输入。接续保留 1 月 5 日全部 2,294 股和 4 月 1 日已完成的 1,534 股；后者仅新算 767 股。完整日期的私有明细还核对本地和持久副本 SHA。

**20. 汇总明细可重复生成相同字节。** `write_forward_details` 按代码排序 JSON，gzip 使用固定文件名和 `mtime=0`，原子替换后才登记持久文件。完成顺序改变或发布中断后重新汇总，明细哈希仍稳定。

## 四、让验收和成本记录也能接续

**21. 保存已完成的合同验收断点。** `validate_contract_record` 将每组完成计数绑定验证器 AST、版本、种子、类型、字段、模型身份、来源页及上下界目录 SHA。再次验收时最多 8 个读线程回读核对全部当前文件哈希，复用已验证计数，避免再次展开二十组数组。文件或验证器改变时重新验证。本次最终覆盖 25 组、211,235,220 行方案输出；行数包含沪市三个留出日的第二套方案，不能当作去重订单数。

**22. 查询旧记录保留未知状态。** `query_phases` 对 416 条没有 `status` 字段的旧快照账本记录单列 `unrecorded`，不推断成功或失败；全部尝试仍计入次数与字节预算。对应兼容和合同恢复检查通过。

**23. 完整计算与接续计算分开外推。** `measured_stage_costs` 逐次保存日期、市场、方案、并发、复用量和新增量。4 月 1 日只新算 767 股，不能用 38.383 秒除全部 2,301 股来估算完整日期。只有完整执行产生 601 日外推值，不混合不同并发配置；601 日没有实际执行。

### 似然内核与完整日评分

8,388,608 行的有界似然内核对照在 16 线程下平均使用 **13.33/13.54 核**，深市、沪市内核约快 **10.18/10.47 倍**。负载复用真实缓存观测，仅用于规模对照，没有改变训练样本或重新拟合。

完整深市留出日共 13,343,055 行、27 页、59 个分层，整数和直方图精确一致，浮点评分及数量假设通过约定误差界。

## 七、仍存在的限制

模型拟合没有完整重测，因此内核加速不能写成完整拟合加速。整页估计和全局评分仍有串行处理与 IO 成本；小样本前向受大股票收尾影响。最终逐页合同、持久文件哈希和统计兼容验收通过，只说明代码满足输出契约；不能将沪市前向完全匹配解释为隐藏属性准确，也不能把两个尾部方案中的任一个自动升为默认。

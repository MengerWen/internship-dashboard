## 补充说明

**深市单股核对。** 引擎接进 344 列的完整流程。300164 上，Python 路径的 344 列与已有参照完全一致；C++ 路径有 631 处响应选择、698 行 BBO 边不同，传到 131 个正式因子值，最大相对变化约 0.57%。把配对选择换回参照后，344 列全部通过。同一只股票，C++ 16 线程的配对 CPU 是 16.5 秒，Python 是 11.8 秒，多用约 40%：单股算得快了，CPU 花得更多。

**深市全期推算。** 晚间修正有效核数的量法：以相邻两日先后进入流水线的间隔为一个周期，包含交接等待，去掉首日填充和末日排空。旧样本里的一个完整周期是 346 秒、4,064 CPU 秒，折合 11.7 核。用同样的权重和成本假设重算，全期 58.33 小时，保守 70.40 小时。没有重跑因子。

**沪市。** 最新完整流程推算全期 17.20 小时，纯计算下限 12.28 小时。和上一轮 C++ 参照的 18 项比较一致，但 Python 与 C++ 之间有 6 个 F40 统计字段、2,059 处超限，最大相对误差约 1e-10；选中的 599.5 万条边本身一致。此前有一轮推算到过 14.30 小时，最新一轮因为目录盘点等待和 F40 耗时回到 17.20 小时。盘点方式试了几种替代，都没更好。深度和九组汇总共用进程池后，这一段从 10.8 秒降到 5.4 秒。

**引擎的去向。** 引擎的构建、开关、资源限制和比较工具都已交付。真实重股上 CPU 收益不够：深市 P75 日的重股和沪市的配对 CPU 普遍增加，只有 300059 降了约 9%。晚间决定：两市场不再等引擎，各自在 Python 路径上达标；引擎另开第二轮，先测生产条件下各部分的 CPU，再按实测改，连续两项改动都没有可测收益就停。第二轮当天没有结果。

**存储。** 深市删掉重复的核对文件约 132 MB；沪市分批删掉 27 个可重建的中间归档约 2.6 GB，原始数据、参数和计时记录保留。两台服务器上引擎的临时代码目录已清理。

**新信号和评价框架。** 用户提出：一个因子的价值可能只在某些时期或市场状态下才显现，不能只看全样本 IC，也不能只看它相对现有信号的单项增量。讨论的结论是把入库和入模分开：有解释、算得对的候选先留下，再按因子族、时间和事先定好的状态做样本外评价；具体门槛等计划。候选工作包括旧预测的周期衰减、信号集中度、分月和分状态评价，以及日频、竞价、行业联动、ETF、期指和其他高频信息。评价框架自己搭；成交、费用和税先不建模，先用每笔毛收益比较不同周期。用户说明米筐可以持续使用。最后要求先写计划，再交给 Codex 实施。

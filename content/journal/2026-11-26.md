## 补充说明

**全链路多波次提速推进（补自 T3 Code 会话）。** 凌晨审定全链路极限提速方案，明确严禁跑全历史正式重算、严禁写正式 S3、坚持 100% 逐位一致（0 ULP）、交易日 08:50–09:35 自动避让，并确立“分析总控与代码/真机执行分工解耦”的工作纪律。全天在 T3 Code 主控调度下从 Wave 1 连续推进到 Wave 9（下午放开 3 路并发限制以加快迭代），围绕沪深因子与定参四格持续做剖析、改写和双机真机复验。

**深市因子与定参。** 五连日与极端日共六份 344 列面板均通过一致性复查（两个冻结参考日逐位对齐，结果写后独立复核）。五连日因子均摊 11.12 秒/日（目标 7 秒/日），极端日 44.50 秒（目标 38 秒），拖尾最重一只股票比最后一只普通股晚 22.71 秒完成。深市定参数值全部逐位通过且无磁盘溢写，极端日少用 341.50 核秒、降至 38.06 秒达标，五连日耗时略有回升。

**沪市因子与定参。** 极端日曾出现一处 1 ULP 浮点微差，改回冻结公式原本的幂函数调用后，单股与全池核对全部通过。晚间默认构建从生产入口跑完四组真机测试：两个因子参考日分别有 709,838 和 711,048 个有限值逐位一致，两组定参各 159 个参数值逐位一致。四组耗时分别为因子五连日 95.33 秒、极端日 138.36 秒、定参代表日 18.76 秒、七月三日 129.29 秒，均未过速度门。晚间合入的匹配派工和图内存释放优化待下一轮真机测量。此前测试的编译器激进优化档（PGO/LTO/本机指令集）在四组对照中只快了两组，因此继续保持默认构建。

**Doris 并发探针。** 夜间用同一日 36 条查询测试 1 到 8 路并发：2 路和 8 路吞吐分别为 323 和 845 MB/s，首行延迟 P95 从 26.28 升至 39.59 毫秒（首次 3 路探针偶发崩溃，重试未复现）。测试结束后账户配额恢复为 2 路。

**本地依赖审计与存储治理（补自 T3 Code 会话）。** 上午对本地目录依赖及双机原生 S3 做了只读全景测绘，确认 `wenjie` 账户 S3 约 290.81 GB（34.3 万对象）、`wangly` 约 314.10 GB（43.0 万对象），并摸清各仓库间的硬路径依赖以防误删。随后合入存储分级规约和对象账本 CLI 工具（支持清理前反查正式索引引用），修复相对键和嵌套索引反查两处缺陷，并分头清理旧编辑器服务端与可重建缓存；部分超大 S3 分区因列举超时仍留待分批盘点。

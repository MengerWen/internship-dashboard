01 · Portfolio

三种收益口径彼此独立

纯多：每天买入预测排名前 20%。

纯空：每天卖出预测排名后 20%，收益按空头 PnL 记号。

多空：每天买入前 10%、卖出后 10%。

02 · Annualization

Sharpe 来自收益，不是 ICIR

annual mean = mean(rdaily) × 252
annual vol = std(rdaily, ddof=1) × √252
Sharpe = mean(rdaily) / std(rdaily) × √252

RankIC 单独报告，不进入组合 Sharpe 的分子或分母。

03 · Ties

为什么有两种分位结果

Tie-neutral：边界遇到相同预测分数时按分数块的分数化成员权重分配，避免股票代码顺序决定入选。

Exact floor：稳定排序后严格取 floor(20%N) 或 floor(10%N)。树模型和 CUDA LightGBM 大量 ties 时，两者可能明显不同。

Formal Design Freeze

为什么 Freeze 只有四个模型？

Freeze 不是“把 14 个模型都送进 Final”的模型清单，而是只用 Development 指标、注册 selector、PBO、portfolio、attribution 与自动审查合同选出的 1–5 个确认性 pipeline。其余 family 没有在 Freeze 后被重新选择或调参。

本页额外展示的 all-14 Test 是 Final labels 已打开后的补充审计。它回答“所有模型结果如何”，但不能追溯性地改变 Freeze，也不能升级为新的正式 Final evaluation。

Implementation reconciliation

同名模型的不同结果，为何都要保留

LightGBM

CUDA formal ≠ CPU posthoc

正式冻结预测在 CUDA 上运行；all-14 posthoc 没有复现 backend freeze，得到 CPU 实现。两者 key 相同但 score 不逐位相等，最大绝对 score 差约 1.3908，因此表格和图例分成两个结果，不能拿 CPU 数值替换正式 CUDA。

XGBoost

Dev CUDA 与 Test CPU 不连线

Development OOF 的冻结 runtime 允许 XGBoost 使用 CUDA；posthoc Final 是 CPU 审计结果，未满足冻结 backend。图上用两条只覆盖各自阶段的虚线表示，不制造跨阶段连续性。

Frozen equality

三条 frozen 预测逐位一致

Raw Ridge、Raw Elastic Net、Regression Tree 的 posthoc prediction 与正式 sealed prediction score bitwise equal，可安全用同一条 Test 曲线展示。LightGBM 是唯一 frozen family 的 backend 差异。

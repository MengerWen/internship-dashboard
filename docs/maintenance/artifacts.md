# 文件与临时产物维护

正式源文件保留在原有 `content/`、`site/`、`scripts/`、`tests/` 等目录。未发表正文放在 `docs/drafts/`，避免被 `build.py` 扫入每日汇报。研究记录保存在 `docs/reports/`；历史结论仍以其写作日期和证据范围为准，归档不代表重新验收或批准实施。

## 新任务

- 截图、预览、完整站点副本、构建与调试日志写入 `.local/runs/<任务>/`，该目录不进入 Git。
- `scripts/verify_journal*.cjs` 默认使用上述目录；`JOURNAL_ARTIFACT_DIR` 可显式指定其他位置，原有 `JOURNAL_BASE_URL` 等输入不变。
- 默认复用同一任务目录；需要保留多轮现场时，在任务目录内按实际轮次区分，并记录用途。避免每次运行无条件复制完整站点。
- 仍在使用或失败待查的现场可写 `run.json`，记录 `task`、`status`、`reason`、`review_after` 以及相关源码 commit；其中日期由任务负责人明确填写。

## 任务收尾

1. 保存独有源码、正文和可复用脚本；核对本项提交已推送。
2. 将需要长期引用的验证结果、发布收据和代表截图选入 `artifacts/<任务>/`，注明实际验证范围和源码版本。完整站点、可重建压缩包和重复日志保留在临时目录。
3. 核对本任务输出是否仍有运行引用、独有修改或未保存成果，再清理可重建内容。普通文件操作遵守既有 PowerShell、路径边界和权限规则。
4. 运行 `npm run workspace:audit`。未跟踪条目必须有去向；临时输出超过 1 GiB 时复核。该命令只读，不清理、不暂存、不提交。

已完成任务的临时输出默认保留 7 天。到期用于提醒复核，不能仅凭时间、扩展名或目录名认定可删。需要继续保留时记录原因及下次复查日期。每周或明显超量时运行同一个盘点入口即可，无需另设自动删除任务。

详细 JSON 可用 `python scripts/workspace_inventory.py --json`；容量检查可通过 `--max-local-mib` 指定本次上限。扫描不跟随链接，并会报告读取错误和链接。

## 历史积压

2026-10-30 清理只覆盖当日登记的积压清单。完整清单、独有内容保存位置及实际删除结果见本目录下的本次清理记录。其他目录或未来文件须重新核查。

已跟踪的历史证据继续可用；后续归档或清理通过新提交记录，不改写已发布 Git 历史。

# 汇报仓库积压文件清理实施计划

> 执行方式：当前会话在汇报仓库 main 串行完成；用户已授权处理积压内容。既有项目规则优先，不创建例行 worktree，不启动研究计算或公司服务器任务。

**目标：** 保存独有正文、脚本及必要验收证据，删除核查过的重复和可重建副本，并为后续临时产物提供统一输出及只读盘点入口。

**范围：** `D:/MG/！Internship/BUILD/汇报` 当前未跟踪文件，以及明确列入核查清单的大目录内部生成内容。初始 main 为 `4fe8211e022372538d967032ba2b2b15171c8d64`，初始未跟踪文件 21,376 个。其他项目的临时目录、进程和文件不在清理范围。

**技术栈：** Git 内容对象、Python 只读内容审计、PowerShell 原生文件操作、Node 验收脚本。所有可控制模型调用使用 gpt-6.1-sol / xhigh；本任务不生成译文、不派生子代理。

## 1. 只读核查

- 记录当前 Git 状态、远端 main、进程引用、目录链接、未跟踪清单及文件哈希。
- 对整站副本、源文件快照、tar 成员与 Git 可达历史逐份比对；识别独有源码和不可重建证据。
- 完成条件：每个删除目标有绝对路径、用途及内容去向，所有独有成果已找到保留位置。

## 2. 保存成果

- 将未发表日报与研究记录保存为明确标注的历史草稿或方法记录，保持内容真实，不将历史草稿自动发布为新结论。
- 保存可复用脚本、原型源码、独有验收结果及必要截图；保留实际失败和未验证状态。
- 完成条件：保存内容通过内容核对，独立 commit 后 push，并核对 GitHub 包含目标 commit。

## 3. 分批清理

- 清理前再次核对目标边界、链接、运行引用及已保存内容。
- 删除采用 PowerShell Remove-Item -LiteralPath，普通删除不加 Force；删除与复制、停止进程、Git 提交及写收据分别执行。
- 拒绝、占用、只读或权限问题保留现场并记录；不更改权限和命令策略，不绕过拦截。
- 完成条件：逐项核对实际删除结果及保留原因，记录文件数、字节数和审计清单。

## 4. 防止再次堆积

- 新验收输出默认集中到 `.local/runs/<任务>/`，必要证据由人工挑选到已跟踪的 artifacts 目录。
- 添加只读盘点入口，包含未跟踪文件与临时目录容量；不根据时间自动删除未知内容。
- 在项目维护说明与 AGENTS.md 添加临时产物创建、任务结束和清理时的明确入口。
- 完成条件：相关单元检查、Node 脚本语法检查及实际只读盘点通过，完成 commit、push 和远端核对。

## 5. 最终核对

- 核对初始清单内每项去向、未知未跟踪文件、临时目录及清理脚本自身的临时文件。
- 报告本地提交、GitHub 推送、磁盘回收和遗留原因；不将 push 说成服务器同步或实际部署完成。

本计划按 writing-plans 技能规定存放于此目录；实施对象为汇报仓库，本计划不触发研究仓库提交或服务器运行。

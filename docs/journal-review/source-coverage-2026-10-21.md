### Claude 真实会话 ID 没有逐消息处理

同一物理 JSONL 可以保留原会话和续接会话的消息。当前采集器把首条用户消息之前读到的 `sessionId` 用作整份文件的 ID，没有在 `scan_file()` 中保留每条消息实际的 `sessionId`。

对本次索引中的 122 份 Claude 文件逐消息回查，18 份存在混合 ID，83 条消息被归到错误 ID；这 83 条的行哈希均不同。新索引按文件归属合并后是 555 个（平台、会话 ID），按消息实际携带的 ID 则是 573 个，尚未加入上述 4 份被排除会话。这些数字都不是独立研究任务数。

用户提供的 `749c4a13` 原文件内容归属正常，但其继承副本也被整份归到 `749c4a13`，包含了另一会话后来新增的消息。已选清单中的 12 条 Claude 摘录逐行检查，未发现这一 ID 错配；不能把候选索引缺陷说成这 12 条摘录已经全部错引。详见 [audit-verdict.json](../../data/journal-source-audit-2026-10-21/audit-verdict.json)。

### 真实用户选项回复被整段过滤

当前 `WRAPPERS` 把 `<send_user_message_question_reply>` 整段排除。这个标签也用于真实用户通过界面提交的回复，不能与系统提示混为一谈。

## 为什么之前的检查没有挡住遗漏

原因可以从当前代码和原始审计记录直接核对。

1. **报告不属于自动材料采集的独立输入。** `collect_journal_evidence.py` 对研究仓显式读取的是配置中的 `PLAN/`。`reports/` 中已提交文件会出现在 Git 变更路径里，但不会像计划一样逐份读取成报告材料；`reports_published` 指的是汇报仓 `content/daily/` 的日报。设计研究经常未提交，依赖 Git 很容易漏掉这类成果。
2. **补会话时以既有日卡为起点。** 上次会话报告明确写“围绕 89 张现有日卡”挑出 94 条摘录。`render_manifest()` 也只遍历已有日卡，验证还要求当天已登记相应链条。这个组件适合给已审阅正文增加来源，却不能承担发现新日期、新目标和新链的工作。将其当成完整补漏流程，空白日就一直空白。
3. **旧链的日期范围限制新候选。** 自动归属用当前链条首末日筛选计划和路径。尚未登记的早期工作、并行目标会受既有范围限制；本次发现的 9 月分组研究，不能靠 10 月才开始的旧链范围自行恢复。
4. **机器待核没有形成处理闭环。** 上一轮补审了 195 条待归属提交，但“提交待核清单”和“报告、未提交文件待核清单”是不同集合。用户报告的同哈希条目依然停在后者。文件已被列出，不等于内容已审阅或已记入正文。
5. **验收对象只覆盖已选集合。** `verify_ref()` 核实选定摘录是否在原文；`verify_journal_sources.py` 核实固定引用的 Git 对象、行号和包含关系；构建及界面测试核实产物结构和显示。这些有价值，但都没有检查“未选来源是否还有重要工作”。`chains_reviewed: true` 也不是对当天所有工作完整性的证明。

因此，不能用旧检查通过来否定本次遗漏，也不应把所有历史结论直接推翻。需要保留已经核实的具体事实，撤回“已完整覆盖全部研究工作”的理解。

## 补正顺序与验收条件

首先修正会话 ID、真实选项回复和项目归属筛选，再重建来源索引。否则一边补内容，一边还会继续丢消息或错记会话。

随后，以来源材料为起点建立逐项处置表。每个实质文件、消息阶段或研究目标都要有去向：已对应到哪一天哪项内容、需要补记、重复参考、排除及理由，或尚缺什么证据。未提交文件、未建卡日期和新目标都应能进入这张表，不能先要求它们属于现有链条。

内容补记优先处理本报告列出的 V 系列、B/C/D 研究、9 月分组定标、成交假设，以及 13 个空白活动日。接着复核[优先文件清单](source-coverage-2026-10-21/priority-files.md)中的旧待核报告和历史笔记。已有 10 月 16 日的撤销结论、模型因果复算等记录继续保留，按实际目标和阶段补前因；不能把每份文件都拆成一条新链，也不能只因前后出现就增加依赖连线。

最终验收至少应同时满足：

- 用户指出的报告及本次确认的缺口均有明确内容去向；日期由消息和写入/运行收据支持。
- 所有候选均有处理状态，待核项单列；不能只给已选部分做真实性验证。
- 会话 ID 按原始消息正确保留，真实用户选项回复可恢复；从原始来源重新采集后，既有摘录验证可以复现。
- 计划、讨论、写入报告、实现、实际运行和效果验证分别记，未采用和撤销记录保留。
- 去重后的别名、原文与副本分开，其他任务的新成果不冒算历史遗漏。
- 内容补记后再检查日卡、链条与网页；界面检查不代替来源覆盖检查。

本次交付是排查结果和可执行的复核队列。历史正文尚未重写，采集程序缺陷尚未修复，不能报告为“日志已经补全”。

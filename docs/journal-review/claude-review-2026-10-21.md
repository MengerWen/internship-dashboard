## 一、语言问题

### 1. 免责句代替内容

207 条要点里有 37 条（18%）带“不能写成”“不等于”“不代表”“不冒记为”“不把……当成”之类的句子。它们大多不是研究上的保留意见，是 Codex 在防自己被质疑说夸大，读者用不上。典型例子：

| 日期 | 原句 | 问题 |
|---|---|---|
| 07-11 | 已有代码不等于全市场结果已验收。 | 没人会这样理解，删掉即可 |
| 07-20 | 回退不等于放弃整条因子研究方向。 | 同上 |
| 07-29 | 未采用的是旧筛选方案，不是当天全部工作。 | 同上 |
| 08-05 | 当天记录集中在历史结果的解释与报告发布。 | 空句，没说任何事 |
| 08-26 | 方法文档有8月26日写入记录，不能只保留8月28日的Git入库点。 | 这是日志自己怎么定日期的内部说明，不该给读者看 |
| 09-13 | 本日记录的是保留决策，不将后续日期的完成数量倒写到这里。 | 同上 |
| 09-17 | 这里记录报告发布，不冒记为当天重新计算全部因子。 | 同上 |
| 09-28 | 原始写入与三次修改在当日16:10–16:11完成 | 文件写入时间对读者没有意义 |
| 10-19 | 文档里的后续比较不冒记为已运行。 | 不仅是套话，而且错了，比较当天已经算完（见第二部分） |

真正有研究含义的保留意见要留，但要写成一句平话。比如 08-02 的“固定参数回看定标日以前的数据，不能直接称为样本外结果”，可以改成“参数是用后来的数据定的，这段历史不算样本外”；10-18 写“分组毛收益未扣成本”就够了。

完整的 37 条见文末附录 A。

### 2. 审计和工程黑话

标题、要点和链条说明里大量用 Codex 自己的工作词汇，读者要猜意思：

| 词 | 实际意思 | 建议写法 |
|---|---|---|
| 签收、改签 | 某个版本确认通过 | 验收通过；沿用原版本 |
| 有界验收、有界取数 | 小范围验收；分页、限量地取数 | 小范围验收；分页取数 |
| 封存、冻结 | 存档固定、以后不再改 | 固定 / 存档 |
| 身份（新身份、科学身份） | 代码和参数的版本 | 版本 |
| 合同 | 约定好的输入输出规格 | 规格 / 约定 |
| 准入、门 | 性能或正确性的门槛 | 门槛 |
| 凭据、凭证、回执 | 运行留下的记录 | 记录 |
| 回读 | 写完再读回来核对 | 写后核对 |
| 退役载荷、热暂存 | 不再需要的文件；本地临时文件 | 照实写 |
| record_only | 只记录性能，不当通过条件 | 照中文写 |
| canary | 小样本试跑 | 小样本试跑 |

最难读的几处（原文照录）：

- 10-21 标题：“六核P75冷启动通过准入，沪市局部验收后因缓存阻塞”；要点：“旧40日不改签，结构与全期冻结未完成”。

### 3. 正文模板段落

每张日卡的正文都重复同样几段：

| 段落（节选） | 出现次数 |
|---|---|
| 以下固定文件核对定义、输入与结果范围；入库日、归档日和实际运行日分别解释…… | 89 |
| 以下摘录补充当时的要求、决策或讨论背景。……摘录不单独证明执行完成、性能或发布状态。 | 88 |
| 本日已匹配会话、原生消息定位……材料阶段表示用途，不等于对应验收通过；……不能签收全部来源。 | 101 |
| 本日有已确认写入的研究材料（标题对应冻结版本，不表示写入时已经包含最终全文）： | 78 |

每条会话摘录后面还挂着“原始 JSONL 第 1518 行；行 SHA-256 前12位 `606a1896569c`（完整值存于审阅清单）”，共 94 处。这些是核查用的定位信息，放进折叠的“原始记录”就行，不该出现在正文里。

19 张卡另有“日期与结果说明”一节，基本是 Codex 在为自己的归链辩护，例如 09-11：“该研究交付不能只归为报告发布”“环境核验不能证明整库300秒达标，也不构成wangly环境对老库的依赖”。

### 4. “原始依据”多半不是当天的依据

“原始依据”一节列的是链条级的固定参考链接，不是当天的证据。357 个能判断日期的链接里：

- 66 个（18%）指向卡片日期 3 天以后才出现的文件；
- 43 个（12%）指向 2 周以前的文件。

例子：

- 7-23 的看板提交“fix(docs): render daily report formulas”被当成“汇报发布”的原始依据，挂在 21 张日卡上，包括 8-20 和 9-11；
- 10 月的计划“深市老因子分组定标：定档预检”挂在 8 月、9 月的 11 张日卡上；
- 8-20 那张卡引用了 9-01 的计划和 9-11 的结果。

读者会以为这些就是当天做事的依据。要么改成当天真正的提交和文件，要么把这节挪到链条页。

### 5. 链备注：模板句、截断、照抄标题

334 条链备注里：

- 43 条是模板句，没写当天做了什么。“盘点存储、保留范围与清理记录”12 次，“整理、补写与发布研究汇报”10 次，“核对五分钟因子及定标过程记录”8 次，“核对服务器取数与迁移过程”6 次，“整理因子构建”3 次，“核对正式因子引擎的实现过程”2 次，“整理论文复现及Notebook讲解”2 次。
- 7 条被截断，以“…”结尾，比如“整理无随机森林 14 模型：Developme…”“讨论深市盘口回放会话研读+基础正确性审计+全量…”。
- 18 条直接照抄会话或材料标题，比如“讨论研判C7.1”“讨论评估葫芦因子1”“整理撤单是否具有固定的等待节奏？”。

这些备注背后多数有真实来源，只是没写出内容。比如 8-14 那条来自会话“评估因子逻辑复杂度”，8-17 来自“扫描并清理服务器冗余文件”，10-19 来自“wenjie与wangly存储扫描”。完整清单见附录 B。

### 6. 其他

- 要点前缀混乱：“构思／方法核查：”“构思／决定：”“实施（文档整理）：”“运行／排障：”“决定／保留方式：”“数据核查／分类讨论：”，十几种写法，读者分不清有什么区别。
- 正文的材料分类“构思（计划文本）”“资料整理”“验收（检查记录）”“运行（过程记录）”“实施（工程记录）”，是 Codex 自己的分类法，没有解释。
- 标题普遍是“做了 A，做了 B，做了 C”三项并列，看不出哪项最重要。

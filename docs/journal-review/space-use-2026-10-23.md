# 同日浮窗的一侧堆叠修正

用户截图中的 2026-10-22 有四项工作。旧布局围绕每个原点单独选位，在右侧不断向上堆叠，左侧空位没有利用。上一轮验收只检查次序、重叠和引线，漏掉了这个问题。

## 修改

同日浮窗先按整组分配横向空间，再安排上下错落。宽度足够时为每张卡片预留卡宽和 14px 间距；宽度不足时使用整个可见图面的宽度。整组两侧留白保持平衡，左右次序和原点位置保留，由引线连接偏离原横坐标的卡片。单点阅读沿用靠近原点的位置，整链排布不变。

继续使用已核对的设计技能及既定视觉；技能文件的哈希复查未见变化。采用 diagnosing-bugs 补充能复现用户症状的检查，先验证旧版失败，再验证修正通过。impeccable 的 layout 检测为 `[]`。

## 同场景对照

以 `35ea1ee8cdde19c89fdbddf7d597ff3dbcf708c4` 的浮窗代码为旧版。使用相同内容、2560×1249 CSS 视口、1.5 倍像素比，输出 3840×1874 截图。

| 检查项 | 旧版 | 修正后 |
| --- | ---: | ---: |
| 可用横向空间 | 1206px | 1206px |
| 四张卡片及间距所需宽度 | 828px | 828px |
| 整组实际横向展开宽度 | 416px | 828px |
| 整组纵向跨度 | 796px | 250px |
| 相邻卡片的横向重叠 | 3 组 | 0 组 |

修正后两侧留白差小于 1px。1440px 和 1024px 视口同样容纳四张卡片横向展开；768px 宽度不足时保持顺序并上下错落。对照图与数字保存在 `artifacts/journal-space-use/`，脚本为 `scripts/verify_journal_space_use.cjs`。

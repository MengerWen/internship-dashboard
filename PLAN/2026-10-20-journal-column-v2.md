# 研究日志第二轮：转竖向推进流，补逐点注解与去留标记

**Goal:** 把「研究日志」的图谱从横向时间轴改成竖向推进流，给每一天、每一个点留出放文字的位置，让链条彼此分得开、悬停时看得清，并把「当时做了、后来没被采用」的工作在图上标出来。

**Architecture:** 保留第一轮全部数据管线与非图表部分（采集脚本、`content/chains.json`、`content/journal/*.md`、`build_journal()`、manifest、清单视图、日卡、链条卡、键盘、路由、索引页、离线内联）。只重写 `site/js/journal.js` 的图谱绘制层与 `site/css/journal.css` 的图谱样式，并在三份数据契约上各加一组字段。

**Tech Stack:** 不变。原生 SVG + CSS，无框架；Python 构建；Playwright 验收。

依据：第一轮 PLAN `PLAN/2026-10-20-journal-column.md`、设计文档 `docs/plans/2026-10-20-journal-column-design.md`、方向记录 `direction-approved.md`。本轮只给方案，不实施。

## 0. 现状实测（改之前先把问题量化）

读的是已实现的 `site/js/journal.js` 与 `content/chains.json`、`dist/manifest.json`：

- 横轴 `x = 148 + (d - first) / (last - first) * 1060`，120 个自然日摊在 1060 个单位上，**每天 8.8 个单位**；`.journal-atlas` 的 `min-width: 1120px`，在 1360 宽的容器里约 1 单位 ≈ 1.06px。
- 轨道高 `36 + 9 × 链条数`；轨道内每条链各占一个固定 y，间距 `(高 - 22) / (链数 - 1)`。
- **「因子与定标」8 条链 → 轨道高 108、链间距 12.3 单位（约 13px）**，而点的半径最大 7（直径 14px）。**相邻两条链的点必然互相压住**——这就是你说的第七条「链与链之间的线挺难看出区别」的直接原因，不是错觉。
- 链名画在该链第一个点上方 9px，碰撞处理只有「与上一个标签横向距离 <76 单位就上移 10px」一条，所以 17 个标签里好几个仍压在点上。
- 实心点与刻度行现在用的是 `d.report`（= 这天的工作写进了哪篇汇报），但图注写的是「实心点有汇报」，刻度行标题写的是「每日汇报 N 篇」。**三处说的不是同一件事**，顺带要统一。

### 一个关键测量：两个轴的资源配反了

| 轴 | 要放多少东西 | 现在给了多少 | 转 90° 后 |
|---|---|---|---|
| 时间 | 120 个日期刻度 | 宽度 1060 单位 → **8.8 单位/天** | 高度无界 → 7／11／17 px/天 三档 |
| 链条 | 28 条互不重叠的链 | 高度约 430px → **约 13px/条** | 宽度 1300px → **约 42px/条** |

链条轴要放的是 28 个并排的东西，它需要的是**宽**；时间轴要放的是 120 个刻度，
它需要的是**长**，而页面的长度本来就是免费的。现在的横向版把两者放反了。

另外测过一件事：28 条链里大部分在时间上不重叠，理论上可以按 git-graph 打包到 9 条泳道。
**本方案不这么做**——打包会让两条不同的链共用一列，读起来像同一条链，
是对图的简化。转 90° 之后宽度够用，每条链保持自己独立的一列。

## 1. 七个问题的判断

### 第 6 条先答：**把这张链条图整个转 90°，一条链都不去掉**

定了：**不是另做一个简化的竖向列表，而是把现有的链条图旋转过来**。
时间从左右走改成从上往下走，28 条链条一条不少，每条占自己一列，仍按六个轨道分组。
图还是图，仍然是这个栏目的主体。

效果图：`design-demos/journal-prototype/vertical-atlas.html`，用的是已实现的
`dist/manifest.json`，不是示意。截图 `design-demos/screenshots/v3-atlas-*.png`（未选中、点日期、点链名、点单个点、图下方日卡），
对照现状 `v2-before-horizontal.png`。

**为什么转过来比留着横向好——两个轴的资源刚好配反了：**

| | 时间轴 | 链条轴 |
|---|---|---|
| 现在（横向） | 宽度 1060 单位 ÷ 120 天 = **8.8 单位/天** | 高度约 430px ÷ 28 条链 = **约 13px/条**，点直径最大 14px，必然互相压住 |
| 转 90° 后 | 高度无界（页面本来就滚动），紧凑 7px/天、标准 11px/天、宽松 17px/天 | 宽度 1300px ÷ 28 条链 = **约 42px/条**，点直径最大 14px，绰绰有余 |

链条轴上要放的是 28 个互不重叠的东西，它需要的是**宽**；时间轴要放的是 120 个刻度，
它需要的是**长**，而页面的长度是免费的。现在的横向版把这两件事放反了，所以才挤。

**顺带拿回来的三件事：**

1. **链名有地方写了。** 列头一行竖排链名，每条链一个，28 个名字在 42px 间距下不打架，
   不用再把标签挤在图里互相避让。第 2 条「说明文字放到图的右边」在竖向下就是列头——
   它在图外面、不压住任何数据，而且和第 3 条的悬停联动。
2. **紧凑密度（7px/天）下，六月到十月约 840px，基本一屏看全。** 所以「整段实习是什么形状」
   并没有丢，反而是在链条间距大三倍的前提下拿到的。不需要再额外加一条全景条。
3. **日期刻度有地方写了。** 左侧 86px 的日期栏，标准密度下每个工作日都标得出来，
   紧凑密度下只标周一。横向时这些日期根本没地方放。

**代价**：标准密度下整图约 1400px 高，要滚一屏多；宽松密度约 2100px。
这正是时间轴该花的地方，横向时它被压在 1060 单位里才是真的亏。

**第 4 条的做法同步改回浮窗。** 不做常驻文字——常驻文字会把图变成列表，
那正是上一版被否掉的原因。做法是**每个点一个浮窗**：每个点给一块 18 × (每日像素 + 6) 的
透明命中区，悬停就在旁边浮出一张小纸卡，写日期、星期、提交数、这条链的名字、
**这条链那天在做什么**、是否写进汇报、是否当天发布、是否未采用。效果图里已经做出来了。

### 第 1 条：尺寸与排版的灵活度

现在是写死的 `viewBox 0 0 1240 H` + `min-width: 1120px`，窗口变宽只是整体放大、文字跟着变大，信息密度没有变化。改成：

- **宽度随容器测量**（`ResizeObserver`），几何按实际像素重算，不再整体缩放；文字永远是 CSS 像素尺寸。
- **三档密度**：紧凑（行高 24px）／标准（30px）／宽松（38px）。标准档每行能放下日期 + 一句话；宽松档能再放下每条链的注解；紧凑档只放日期和点，注解收进悬停。
- **泳道宽度随需要的泳道数自适应**，当前筛选只剩一条链时泳道区收到 36px，正文区变宽。
- **三档密度、时间窗、是否显示注解**三个选择存 `localStorage`，刷新后保持。
- 全景条高度固定 150px，不随密度变。

### 第 2 条：链名放到图外面

转 90° 之后链条是列，名字的位置就确定了：**吸顶列头**，一行竖排的链名，每条链一个，
名字立在它自己那一列的正上方。42px 间距下 28 个名字互不打架，11px 字号竖排约 6 个汉字正好。

列头分两层：上层是六个轨道名，带一条横杠标出它覆盖的列范围；下层是各条链的名字。
轨道之间用一条竖线分隔，列头和图里都画。

这比现在把标签塞在图里强在两点：标签不再压住数据点，也不再需要那套「横向距离 <76 就上移 10px」
的避让逻辑——现在那套逻辑仍然让好几个标签叠在一起。

链名同时是悬停目标（见第 3 条），也是「未采用」的标记位（见第 5 条）。

### 第 3 条：悬停一条链的凸起与高亮

**不要真的位移**。点的 y（竖向下是 x）编码的是「这条链在哪条泳道」，把它抬起来等于在说谎。用这四件事表达「凸起」：

1. 把该链的 `<g>` 移到同级末尾（画在最上面），它与别的链交叉处就变成「压在上面」。
2. 线宽 1.7 → 3，并在线下垫一条 5px 的纸色描边（halo），和它交叉的其它链被这条纸色隔开，自然有层次。
3. 该链的点半径 +1，描边加粗；空心点的纸色填充不变。
4. 该链的名字（表头与行尾片）转全墨，其余链名降到 25% 不透明度；该链涉及的日行底色换 `--surface`。

悬停目标要好命中：每条泳道给一条 18px 宽的透明命中条，覆盖该链的整个存续区间，而不是只有线本身。

### 第 4 条：三种点击，三种方向的说明；**不做悬浮**

悬浮在这张图上是坏主意：鼠标停在某处，分不出你要的是**这一行**（这一天）还是**这一列**（这条链），
猜错就是干扰。全部改成点击，三个点击目标对应三种展示，方向各自跟着它的排列方向走：

| 点什么 | 图上发生什么 | 说明怎么摆 |
|---|---|---|
| **日期**（左侧日期刻度，或图上那一行） | 一条珊瑚横线穿过当天所有的点，当天每个点加珊瑚圈；当天涉及的链名在列头转珊瑚，其余压暗 | **横向排开的卡片**——当天的点本来就是横着的，卡片就横着排，一张对一列，用折线引回自己那一列；重叠就依次右移，整组超出右边界就整体左移 |
| **列头的链名** | 整列转珊瑚加粗，其余列压到 13%；该链名转珊瑚，其余链名压到 20% | **纵向排开的注解**——这条链的点本来就是竖着的，注解就贴着列竖着排，每条写「日期 + 这天这条链在做什么」；挤了就依次下推并用引线连回各自的点；列偏右时注解翻到列的左侧 |
| **单个点** | 只有那一个点加珊瑚圈，只有它那条链名转珊瑚 | **一张卡**，就在那个点旁边。日期横线仍然画出来，用来定位是哪一天 |

**图下方始终有一块完整说明区**，就是你截图里那块：
点日期或点单个点 → **日卡**（日期、星期、提交数、这天的标题、链名、做了什么、脉络、根据、计划、
覆盖这天工作的汇报、这天发布的汇报）；点链名 → **链条卡**（上下游、落成了什么、这条链上的每一天）。
两张卡里的链名、相邻日都可点，点了就切到对应的选中状态——图和说明区是同一套选中。

Esc 或点空白处取消选中。

**仍然要改数据契约**：一天可能同时在三条链上，现在只有一句 `headline`，
上面每一种展示要的都是每个 (日, 链) 各一句。`chains` 从 id 列表改成对象列表带 `note`，
`note` 不超过 **24 字**（横向卡片和纵向注解都按这个宽度排版）。
实测 88 天合计 **125 条**注解要人写（22 天已有的 `highlights` 可以拆过去，剩 66 天新写）。
这是本轮最大的一笔内容工作，脚本只能起草。

### 第 5 条：标出「当时做了、后来没被采用」的工作

先说实测结论，免得按错误的假设去实现：

| 想用的信号 | 实测 | 可用性 |
|---|---|---|
| 代码是否还在 HEAD | 24 条链里 22 条存活率 ≥97%，只有「因子引擎」77%、「wangly 环境」80% | **不可用**，这个仓库几乎不删东西 |
| 链条没有下游、也没有收口 | 28 条里只命中 1 条（模型报告），因为 `closes_into` 已经填了 24 条 | **不可用** |
| PLAN 标题写明 Superseded | 2 份（两份 2026-07-15 的 Doris 数据访问计划） | 可用，但稀疏 |
| 提交信息里的回滚与转向词 | 约 20 条 `Revert "..."` 集中在 08-07、08-12；另有 07-01「转向：检测踪迹」、07-10「弯路……」「改方向，写计划」、07-20「lifecycle rollback」、07-29 PLAN「取消价格硬门」、09-03「取消定标候选边物化」 | 可用，且分两类 |

两类要分开，不能混成一个标记：

- **日内回滚（微观）**：08-07 一天 11 条 Revert，是当天性能尝试没成，属于那一天的质地，不是「研究被舍弃」。做法：在日卡的「根据」里统计「本日回滚 N 次」，图上不另加标记。
- **方向性放弃（宏观）**：07-01 的转向、07-10 的弯路、07-15 两份被取代的 Doris 计划、07-29 取消价格硬门、09-03 取消候选边物化。**这才是你要标的。**

所以判定不能自动做，和链条归属同一套架构：**脚本给候选，人下结论，结论入库**。两级字段：

```jsonc
// content/chains.json 的链条级
{"id": "...", "fate": "landed | folded | parked | dropped",
 "fate_note": "被 2026-07-15 的批量访问方案取代"}
```

```yaml
# content/journal/YYYY-MM-DD.md 的日×链级
chains:
  - id: gates
    note: 价格硬门三参数联合定标
    outcome: dropped
    outcome_note: 07-29 决定取消价格硬门，改用 Xq=10% 硬数量门
```

- `landed` 进了最终成果；`folded` 并入了别的线（有延续或派生出去）；`parked` 停在那里、既没否定也没下游；`dropped` 明确被取代或取消。默认 `landed`，只有确实不是的才写。
- `outcome` 不填就继承所属链条的 `fate`。

**画法用形态，不用颜色。** 颜色在这套纸墨体系里已经只剩「当前选中」一个含义（珊瑚），再引一个色就要重新论证整套配色；而「是否被采用」是个二值状态，形态足够表达：

- `dropped` 的点：**画成「×」**，不是空心圆。实测过：空心细边的圆和普通空心圆几乎分不出来，
  在 5–14px 的点上差别太小。换形状才看得见——一个 2px 圆头的叉，和实心圆、空心圆都不会混。
  进出它的线段改 `--muted` 点线（`1 3`）。
- `dropped` 的注解文字：`--muted`，末尾加一个 1px 描边的小片「未采用」。
- 整条链 `fate: dropped`：泳道线全程点线，表头链名加同样的小片。
- `parked`：线正常，末端画一个空心方块（对照 `landed` 的实心方块收口）。

图注里加这三种形态的说明。颜色仍然不动：`tokens.css` 里只有 `--danger: #ad4339` 可用，
但它和 `--focus: #d9654f` 都是暖红，小尺寸下会和「当前选中」混；而换成「×」之后形态差别已经够大，
不需要再借颜色。

**内容工作量**：先把上面 6 处宏观候选逐条确认，再逐链填 `fate`。预计实际为 `dropped` 的不超过 5 条链、10 个日×链条目。

### 第 7 条：链与链分不开

根因在第 0 节：现在每条链只有 13px，点直径最大 14px。转 90° 后变成约 42px，这是主要的解法。
在此之上再做三件：

1. **纸色描边**：每条链的线画两遍——先 5px `--bg`，再 1.7px `--text`。交接弧横穿各列时，
   与链条线的交叉处就有明确的上下关系，不会糊成一团。
2. **点的纸色外环**：每个点先画一个 `r + 1.8` 的纸色圆再画点本身。同一列上相邻两天的点
   （紧凑密度下只隔 7px）因此读成一串珠子，而不是粘成一条。
3. **列底线**：每条链在其存续区间内画一条 1px `--line-soft` 的竖线，中断（虚线段）处仍看得出
   这一列还在。

**不做泳道打包。** 见第 0 节的说明：打包会让两条链共用一列，是对图的简化。

另外把现在的虚线规则收紧：只对**超过 3 天**的空档画虚线，3 天以内按实线连。
实测大部分链条是跳着做的，现在的规则让整张图大半是虚线，实线反而少见，区分度被稀释了。

## 3. 竖向链条图的几何

```
┌─ 吸顶列头 ─────────────────────────────────────────────────┐
│   数据与服务器    快照与回放   算法痕迹      因子与定标        │  轨道名 + 覆盖范围横杠
│  ─────────────  ──────────  ─────────  ──────────────────  │
│   上 D w D 存    L 回       文 a 因 门   历 o 撤 深 老 沪 分 深 │  链名竖排，每条链一列
├─ 图 ───────────────────────────────────────────────────────┤
│ 6月 ─────────────────────────────────────────────────────  │
│ 06-23  ●                                                   │
│ 06-25        ●                                             │
│ 7月 ─────────────────────────────────────────────────────  │
│ 07-06            ●──┐                                      │
│ ……                   └──●                                  │
└────────────────────────────────────────────────────────────┘
```

- **左侧日期栏 86px**：月份横线与月份名；标准／宽松密度下每个工作日标日期，紧凑密度下只标周一。
  发布过汇报的日子在日期栏右缘画一道墨色短刻度。
- **列宽** = `(容器宽 - 86 - 18 - 18 - 轨道间隔×5) ÷ 28`，下限 22px；当前约 **42px**。

## 4. 交互

1. **没有悬浮态。** 鼠标移动不触发任何展示，只有指针变成手型提示可点。
2. **三个点击目标**见第 1 节第 4 条：日期刻度／图上那一行、列头的链名、单个点。
   三者互斥，点新的就换，Esc 或点空白取消。
3. **选中状态是全局的**：图上的高亮、列头的高亮、图下说明区三处同步，
   说明区里的链名和相邻日也是点击入口。
4. **密度三档**（紧凑 7 / 标准 11 / 宽松 17 px 每天）与**时间窗**（全部／近 3 个月／近 1 个月），
   选择存 `localStorage`。切换密度后保持当前选中。
5. **键盘**：Tab 在日期刻度与列头链名之间移动，Enter 选中；选中一天后 ↑↓ 换一天，
   ←→ 在当天涉及的几条链之间切换到「单个点」；Esc 取消。
6. **动效**只保留选中切换（120ms）与说明区更新（220ms），`cubic-bezier(0.23, 1, 0.32, 1)`；
   `prefers-reduced-motion` 下只留不透明度。
7. **窄屏**：图保留横向滚动（列宽下限 22px，28 列至少 700px），默认仍切到清单视图；
   横向卡片在窄屏下改成竖着堆叠（宽度不够横排）。
